## 8.1 输出对象里有哪些字段

移动端配置页使用 **`computeAttrsFromConfig`（`common/attrCalculator.js`）** 对当前本地配置即时计算；`GET /api/attrs` 仍可对每个单位（`主将`、`副将1`～`副将3`）返回与之一致的结构（供其它客户端或调试）：

- **`风格`**：字符串，规则见 [07-属性点与风格.md](./07-属性点与风格.md)。  
- **`角色分类`**：回显配置中的值。  
- **基础战斗属性**：气血、精力、攻击、防御、速度。  
- **特殊战斗属性**：命中率、暴击率、反击率、致命率、法爆率、反震率、躲避率、抗物理、抗玄击、抗封锁、抗扰乱、抗围困、抗风沙、抗妖火、抗毒术、抗落雷、暴击力、穿透率、爆伤力、法伤力、连击率、连击数、法穿率。

（字段集合与 `common/attrCalculator.js` 中数组一致。）

## 8.2 计算流水线（四步 + 实现细目）

实现文件：**[`common/attrCalculator.js`](../../common/attrCalculator.js)**。主将见 [主将.md](./主将.md)、副将见 [副将.md](./副将.md)。

**步骤 1 — 加法得有效四维**  
`修正属性分配` 后的体质/智力/力量/敏捷，与主将 **装备宝石（及龙骨靴等）** 或副将 **九颗宝石** 提供的四维 **同名相加**，得到 **有效四维**。

**步骤 2 — 四维对应五条基本战斗属性 + 职业原始项**  
用有效四维、等级、`等级系数`、**战斗职业轴** 代入主将/副将公式，得到 **气血、精力、攻击、防御、速度**；并并入 [职业加成.md](./职业加成.md) **§1** 中与该轴对应的七项常数（`职业原始战斗属性`）。**穿透率** 等未在 §1 表中的字段本步为 0，由步骤 3 起叠加。

**步骤 3 — 全部加法型增幅叠加**  
将步骤 2 结果与：主将 **装备余量**（已扣四维）、**坐骑**（仅主将）、**天赋加法部分**（爆率、躲避、暴击、忽视、法系伤害类天赋等）、**帮派**（仅主将）、**默契**（仅副将）等 **同一字段全部相加**。

**步骤 4 — 全部乘法型增幅连乘**  
**强攻**、**强血** 在完成步骤 3 之后生效：对 **攻击**、**气血** 分别乘以各槽 `天赋百分比` 折算的因子 **连乘**（∏(1+p/100)；多槽同名各乘一次）。  

**实现细目**：`mergeNumericObjects` 完成步骤 3；再对合并结果中的 `攻击`、`气血` 乘 `收集天赋乘系数`；调试分层中 **天赋(加法)** 与 **天赋(乘法·整体)** 分列；取整与负数截断规则不变。

## 8.3 仍为占位或可调整项

- **坐骑**：已按 [坐骑.md](./坐骑.md) 实现文档所列种类；未写入文档的列表内坐骑仍为 0 加成，扩展需同步改 `坐骑战斗加成`。  
- **主将** 文档中武人条未写「体质×20」，实现按原文；若与客户端不一致可改 `主将战斗基础`。  
- **等级系数** 使用通式 `20 + 4×⌊(L−1)/5⌋ + (L mod 5 段内偏移)`；155–160 级若需与个别旧表逐点对齐再单独校正。  
- **天赋**：加法类在步骤 3；**强攻 / 强血** 在步骤 4 对攻击/气血整体连乘；其余到字段的映射（如法系伤害天赋 → `法伤力` 系数）仍为简化。  
- **无双形态内成长**（无双等级×0.001）等纯战斗内逻辑未写入静态面板；`/api/attrs` 与本地计算均含 **默契**、**帮派** 等已配置项。  
- **职业抗性 / 前世乘算**：由 `职业经历` 等查表，规格见 [职业加成.md](./职业加成.md) **§2、§3**；**尚未** 合并进 `attrCalculator`。

保持 **输入配置结构** 与 **输出字段名** 不变，Mobile「属性」页可无缝衔接。

## 8.4 进程缓存

- **位置**：`nodejs/src/services/configCache.js`。  
- **逻辑**：以用户 ID 为键；缓存 **配置 JSON 快照** 与 **计算结果**；命中则跳过 `computeAttrsFromConfig`。  
- **失效**：`POST /api/config` 保存配置、管理端 **`PATCH` 用户密码** 等会 `invalidateUser`。
