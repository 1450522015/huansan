# 22 · 回合门、事件日志与战况真源

[← 返回索引](./README.md)

---

## 1. 目标

在「**出招前**回合前置已全部发生并写入唯一真源」的前提下，统一服务端编排与持久化边界，使：

- 双方在同一时刻读到**同一套**战局数据与战况累计；
- **战况文本系统**（调试/回归）与 **战斗过程**（动画）均可追溯到**只追加、不随查询再生**的事件；
- **第 N 回合战况**与**第 N+1 回合标题 + 完整前置**在**一次**结算边界内产出（不拆包、不等二次请求）。

本文档为开发与代码实现的**基线规格**；与 [`20-battle-actions.md`](./20-battle-actions.md)、[`21-battle-architecture.md`](./21-battle-architecture.md) 交叉引用。

---

## 2. 术语

| 术语 | 含义 |
|------|------|
| **回合门（Round Gate）** | 进入某回合、**允许收该回合出招前**必须完成的结算流水线（毁/毒/无双、上回合末木牛、围乱封二次判定、行动前速度排名等）；**无则不生行**，有则按固定顺序彼此独立执行。 |
| **回合体（Round Body）** | 该回合在「门后状态」上按速度顺序执行的各单位行动与即时结算。 |
| **唯一真源** | 以 SQLite 战局行 + `battle_rounds` 等已提交数据为准；内存运行态须与之一致提交。 |
| **事件** | 已发生的战斗事实一条；**只写一次**；查询、轮询不重掷随机、不重算。 |

## 3. 时间点（与产品语义对齐）

| 时间点 | 数据池 | 战况文本系统（累计）应反映 |
|--------|--------|---------------------------|
| T1 战局开始、第 1 回合 | 静态配置 + 初始动态（含速度排名） | `第1回合`、`速度排名：…` |
| T2 第 1 回合出招已结算且战局未结束 | 已应用第 1 回合体与回合末木牛后的状态；**且已应用第 2 回合门** | …第 1 回合战况行…、`第2回合`、第 2 回合前置各行（有则显）、行动前速度行 |
| T3 第 2 回合出招已结算且未结束 | 同上递推 | …、`第3回合`、第 3 回合前置… |
| 终局 | 胜负/逃跑/断线等 | …最后一回合战况、**结果描述**（与现有 `战局结束` 逻辑对齐，可渐进补全） |

**硬约束**：T2 中「第 1 回合战况」与「第 2 回合 + 前置」**紧挨执行、同一原子边界**写入客户端可见的 `round-result` 与 DB 累计，**不拆**为两次等待。

---

## 4. 架构分层（推荐形态）

### 4.1 结构化回合真源（游戏准确性）

- 战局运行态、`battle_rounds` 中出招与日志、单位气血/精力/buff/无双字段等保持为**强一致**业务数据。
- 「第 N 回合门是否已执行」由**状态版本**或等价「当前可接受出招的回合号 + 状态已与门后一致」体现；**禁止**在「门未完成」时接受第 N 回合出招。

### 4.2 事件日志 + 投影（调试 + 动画）

- **过程**（`过程` 数组）视为**追加事件**：行动、木牛、下一回合门的 `processRoundStartBuffs` / `processMusou` 产出步骤按**真实发生顺序**进入同一次 `resolveRound` 的返回（便于前端推导「行动后临时态」）。
- **战况文本系统累计**：由编排层根据引擎返回的 **`战况行动系统`** 与 **`战况下一回合开场块`**（含标题与前置投影行）**单次追加**，保证与 T2/T3 一致；**不**依赖进程内 Map 跨请求搬运木牛。

### 4.3 引擎编排（`battleEngine.resolveRound`）

- **第 1 回合**：进入 `resolveRound(1)` 时执行**第 1 回合门**（与现逻辑一致：`processRoundStartBuffs` + `processMusou(1)`），再执行回合体，再执行回合末木牛。
- **第 N 回合（N≥2）**：进入 `resolveRound(N)` 时**不再**重复执行第 N 回合门（已在 **`resolveRound(N-1)` 末尾**执行完毕）；仅执行回合体与回合末木牛。
- **`resolveRound(N)` 末尾**（战局未结束时）：在同一调用内顺序执行 **第 N+1 回合门**（`processRoundStartBuffs` → `processMusou(N+1)`；木牛过程条来自**本回合刚结束的** `processMountEndOfRound`，按展示顺序与门内步骤合并），提交运行态，并生成 **`战况下一回合开场块`**（`第N+1回合` + 前置投影 + 行动前速度行）。
- **终局**：不执行下一回合门；不写 `战况下一回合开场块`。

### 4.4 前置子事件

- 多个前置类型**无联动**，仅**有序 pipeline**；缺省类型不生成展示行。

## 5. API / 字段约定（实现跟踪）

| 字段 | 说明 |
|------|------|
| `战况行动系统` | 本回合 `buildSystemBattleText` 去掉首行「行动后速度排名」后的行（与现语义一致）。 |
| `战况下一回合开场块` | **仅当**本回合结算后战局未结束时存在：`['第K回合', ...前置与行动前速度]`。 |
| `战况回合开始系统` | 兼容调试：建议为 **`战况下一回合开场块` 去掉首行标题** 后的前置+速度，或空（见实现注释）。 |
| `回合末木牛过程` | 本回合末木牛步骤数组（未结束时会并入下一回合门的展示排序）。 |

**废弃**：`待并入本回合前置的木牛过程` 与进程内 `pendingRoundMountSteps`（改由同一次 `resolveRound` 内串联）。

---

## 6. 与 `startRound` 的关系

- `startRound(1)`：仍负责在累计为空时写入 `第1回合` + 首速（与现有一致）。
- **`startRound(N≥2)`**：**不再**单独向累计追加 `第N回合` 标题；标题与完整前置仅在 **`resolveRound(N-1)` 的 `round-result`** 中与上一回合战况**同包**出现。

---

## 7. 迁移与兼容

- 进行中的旧战局：以「重启销毁」策略为主（见 `21-battle-architecture.md`）；新逻辑对新开战生效。
- 前端若依赖旧字段语义，以 `round-result` 为准渐进切换至 `战况下一回合开场块`。

---

## 8. 后续扩展

- 更复杂的无双技能：仅在**回合门 pipeline** 中插入新步骤类型与事件投影；不改变「门 → 体 → 门」总边界。
