## 8.1 输出对象里有哪些字段

移动端配置页使用 **`computeAttrsFromConfig`（`common/attrCalculator.js`）** 对当前本地配置即时计算；`GET /api/attrs` 仍可对每个单位（`主将`、`副将1`～`副将3`）返回与之一致的结构（供其它客户端或调试）：

- **`风格`**：字符串，规则见 [07-stats-style.md](./07-stats-style.md)。  
- **`角色分类`**：回显配置中的值。  
- **基础战斗属性**：气血、精力、攻击、防御、速度。  
- **特殊战斗属性**：命中率、暴击率、反击率、致命率、法爆率、反震率、躲避率、抗物理、抗玄击、抗封锁、抗扰乱、抗围困、抗风沙、抗妖火、抗毒术、抗落雷、暴击力、穿透率、爆伤力、法伤力、连击率、连击数、法穿率。

（字段集合与 `common/attrCalculator.js` 中数组一致。）  
除 **连击数** 等为 **区间文案**（如 `2~3`，战斗内再取区间内整数）外，**其余数值项在最终结果中均为非负整数**（四舍五入）；**强攻 / 强血** 仅在「天赋乘算前」整体取整之后作用于 **攻击、气血**，见 **§8.2**。

## 8.2 计算流水线（步骤 + 实现细目）

实现文件：**[`common/attrCalculator.js`](../../common/attrCalculator.js)**。主将见 [14-main-hero.md](./14-main-hero.md)、副将见 [15-deputy.md](./15-deputy.md)。

**步骤 1 — 加法得有效四维**  
`修正属性分配` 后的体质/智力/力量/敏捷，与主将 **装备宝石（及龙骨靴等）** 或副将 **九颗宝石** 提供的四维 **同名相加**，得到 **有效四维**。

**步骤 2 — 四维对应五条基本战斗属性 + 职业原始项**  
用有效四维、等级、`等级系数`、**战斗职业轴** 代入主将/副将公式，得到 **气血、精力、攻击、防御、速度**；并并入 [16-class-bonuses.md](./16-class-bonuses.md) **§1**：主将使用 `职业原始战斗属性(轴, true)`，副将使用 `职业原始战斗属性(轴, false)`（今世表不同）。**穿透率** 等未在 §1 表中的字段本步为 0，由步骤 3 起叠加。

**步骤 3 — 全部加法型增幅叠加**  
将步骤 2 结果与：主将 **装备余量**（已扣四维）、**坐骑**（仅主将）、**天赋加法部分**（爆率、躲避、**暴击力**（天赋「暴击」）、法爆、反击、致命及 **忽视→`忽视率`** 等）、**帮派**（仅主将）、**默契**（仅副将）等 **同一字段全部相加**。技能类天赋与 [19-talents.md](./19-talents.md) **§19.2** 一致，**不**在本层合并数值，仅写入结果中的 **`天赋技能效果`**。

**步骤 3.5 — 主将速度乘算与「天赋乘算前」四舍五入**  
- **主将**：在步骤 3 合并结果上，先将 **速度** **`Math.round` 四舍五入**，再乘 **`主将前世槽速度连乘系数`**（与 [16-class-bonuses.md](./16-class-bonuses.md) **§3**、`docs/私有文档/职业加成.md` 一致）。例：加算后 **977.5**、倍率 **1.005**（一世异）→ **978×1.005=982.89**，再经本步对其余字段及速度一起取整后进入强攻强血前状态，最终输出再取整得 **983**；**不得**用 **977.5×1.005** 再取整得 **982**。  
- 随后对 **即将参与最终输出的全部数值型战斗字段**（基础五维、特殊战斗属性、`忽视率`）做一次 **`Math.round` 四舍五入** 取整。**连击数** 等为 **字符串区间**（如 `2~3`）的字段 **不**改写。  
- **含义**：战斗侧以 **整数** 为有效值；取整前 **100.9** 与 **100.5** 在参与后续运算时 **均视为 101**（与取整后一致）。  

**步骤 4 — 强攻 / 强血 连乘（仅攻击、气血）**  
在 **步骤 3.5 取整后** 的 **攻击**、**气血** 上，再乘以各槽 **强攻 / 强血** 的因子 **连乘**（∏(1+p/100)；多槽同名各乘一次）。**不得**在未取整的浮点底数上直接乘算再取整，否则可能与「先取整再乘」不一致（例：底数 11894.6、160 级强攻约 **+50%** 时，先取整得 11895，再 ×1.5 → 17842.5，最终输出 **17843**；若用 11894.6×1.5 再取整则得 **17842**。）

**步骤 5 — 输出取整**  
`finalizeBattleResult` 对各项再做 **`Math.round`** 与 **`Math.max(0, …)`**（与步骤 3.5 对已取整的字段为幂等）。对外展示的 **总战斗属性** 均为整数；**连击数** 仍为区间文案，由战斗内按规则取 **2 或 3** 等。

**实现细目**：`mergeNumericObjects` 完成步骤 3；`天赋乘算前战斗属性四舍五入` 完成步骤 3.5；`收集天赋乘系数` + 对 `攻击`/`气血` 相乘完成步骤 4；调试分层共 **5** 步（含「加算未取整」「天赋乘算前已取整」「强攻强血乘算后未最终取整」）。

## 8.3 仍为占位或可调整项

- **坐骑**：已按 [17-mount.md](./17-mount.md) 将文档所列种类并入 `坐骑战斗加成`；**文人技能成功率**、**木牛流马回合末回复** 等仅 `坐骑战斗阶段占位` 标记，待战斗模块接入。未写入文档的列表内坐骑仍为 0 加成，扩展需同步改 `坐骑战斗加成` / `坐骑战斗阶段占位`。  
- **主将** 五维公式（武/文/异）与 `docs/私有文档/主将.md`「配置点转属性」及 [14-main-hero.md](./14-main-hero.md) 一致；见 `主将战斗基础五维`。  
- **等级系数** 使用通式 `20 + 4×⌊(L−1)/5⌋ + (L mod 5 段内偏移)`；155–160 级若需与个别旧表逐点对齐再单独校正。  
- **天赋**：见 [19-talents.md](./19-talents.md) **§19.2**（战斗加算 / 乘算 / 技能标记 / 隐藏 `忽视率`）。  
- **无双形态内成长**（`副将无双成长增量`）不并入 **`computeUnitAttrs`**；副将配置页用 **`computeUnitAttrs副将无双形态`** 与常态结果对比（左侧即面板最终值）。`/api/attrs` 与本地计算均含 **默契**、**帮派** 等已配置项。  
- **主将 · 职业抗性**：`职业经历` 前三世 + 当前世对应抗性，由 `主将前世槽抗性加算`、`主将今世抗性加算` 在加算层与装备等 **同名相加**；规格见 [16-class-bonuses.md](./16-class-bonuses.md) **§2**。
- **前世槽攻/血/速度乘算**：攻、血在 **主将、副将** 的基础五维公式内连乘；**速度**在主将侧于加算合并后再乘，在副将侧于五维内乘速基（副将当前无速度加算项，等价）；见 [16-class-bonuses.md](./16-class-bonuses.md) **§3** 与 `gameCatalog.js`。
- **副将 · 职业经历抗性**：规格仍见 **§2**，当前 **`attrCalculator` 未** 按副将 `职业经历` 叠加抗性（仅主将侧接入）。

保持 **输入配置结构** 与 **输出字段名** 不变，Mobile「属性」页可无缝衔接。

## 8.4 进程缓存

- **位置**：`nodejs/src/services/configCache.js`。  
- **逻辑**：以用户 ID 为键；缓存 **配置 JSON 快照** 与 **计算结果**；命中则跳过 `computeAttrsFromConfig`。  
- **失效**：`POST /api/config` 保存配置、管理端 **`PATCH` 用户密码** 等会 `invalidateUser`。
