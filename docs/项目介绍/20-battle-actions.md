## 2. 物品（九转丹 / 龙涎露）

与私有文档一致：

- **九转丹**：单体、己方任意目标；**恢复至满气血**（按当前气血与最大气血差值结算）；**主将气血为 0 时可拉活**；**副将已阵亡则不可对其使用**。
- **龙涎露**：单体、己方任意目标；**恢复至满精力**；**主将已阵亡仍可对主将回满精力**；**副将已阵亡则不可使用**。
- 行动方 **自身气血 ≤ 0** 时不可使用物品（「封」「乱」尚未建模时服务端可不校验）。

实现：`execItem` 与 `executeAction` 中「物品」分支；客户端物品说明见 `mobile/src/pages/BattlePage.vue` 中 `可用物品列表`。

## 2.5 技能（当前实现范围）

- 前端流程：点击 `技能` -> 二级弹框选技能 -> 选目标 -> 统一提交回合动作。
- 后端结算：`nodejs/src/services/battleEngine.js` 的 `execSkill`。
- 面板值：按 `技能.等级 + 技能.熟练度` 线性插值（非写死当前效果）。
- 精力规则：前端始终可选；后端强校验，不足则行动失败并写日志。
- 坐骑增幅：主将骑乘 `司南车` 时，对文人技能成功率加 `0.1 * 坐骑等级`；主将骑乘 `木牛流马` 时，回合末自动回复（见 §2.6）。
- 神将技增幅：神将已实现（见 §2.8），仅头衔为"神将"的副将可选一个神将技，影响对应技能的伤害/成功率/效果值。
- 已接入伤害型技能：`舍命一击/力劈华山/排山倒海/呼风唤雨/妖火燎原/五雷轰顶/巫蛊极毒/毁天灭地`。
- 已接入控场技能（回合内首版）：`画地为牢/趁火打劫/四面楚歌/金蝉脱壳/暗渡陈仓`：
  - `围`：不可攻击/技能；受任意伤害立即解除。
  - `乱`：行动时原指令失效，改为随机攻击场上目标。
  - `封`：行动时直接失效。
  - `金蝉脱壳`：成功后移除目标 `围/乱/封`。
- 同类 buff 不叠加：目标已有同类 buff 时再次施加无效（保留原状态）。
- `固若金汤`（已接入数值生效）：
  - buff 存续期间增加防御、抗物理、抗法术（抗法术会映射到围/乱/封/风沙/妖火/落雷/毒术抗性判定）。
- `凌波微步`（已接入速度加成）：
  - buff 存续期间提高速度百分比；
  - 后端回合执行改为"每次行动前动态重排"，保证速度变化可影响本回合后续行动顺序；
  - 同时保持"每单位每回合最多行动一次"。
- 跨回合已接入：
  - `巫蛊极毒`：施法当回合造成伤害并附加 `毒`，后续在每回合开始触发毒伤（按等级段衰减）。
  - `毁天灭地`：施加 `毁3` 标记；回合初递减并在计时结束时结算雷伤（主目标）+火伤（同阵营其它目标）；若目标或施法者先死亡则失效。
  - `暗渡陈仓`：附加 `隐` 标记（后端已记录与持续；前端已按规则隐藏）。
- buff 回合数（当前实现口径）：
  - 围/乱/封/固/速/隐：6 回合；
  - 毁：3 回合；
  - 毒：按技能等级表（2/3/6 回合）。
- 隐显示规则（前端）：
  - 敌方单位存活且带 `隐` 时，只显示 buff 文本"隐"；
  - 该单位气血/精力/速度/职业信息全部隐藏；
  - 单位死亡后不显示任何 buff（含隐）。

## 2.6 坐骑战斗阶段效果

- **司南车**：主将骑乘时，文人技能成功率 +`0.1 × 坐骑等级`（`getSkillMountBonus`）。
- **木牛流马**：主将骑乘时，**回合末**自动回复（`processMountEndOfRound`）：
  - 回复气血量 = `最大气血 × 0.001 × 等级`
  - 回复精力量 = `最大精力 × 0.001 × 等级`
  - 比较当前气血/精力比例，**哪个比例更低就回复哪个**
  - 回复量不超过上限减去当前值的差
  - 主将死亡时无效
  - 动画效果：主将亮绿框，横幅显示"木牛流马"，直接熄灭

## 2.7 伤害公式关键规则

- **真实物理抗性**：`clamp(面板抗物理, 0, 100)`，即真实物理抗性上限为 100。
- **有效物理抗性**：`clamp(真实物理抗性 - 攻击方穿透率, 0, 100)`，即穿透率超过对方真实物理抗性时有效抗性为 0。
- **法穿率上限**：`clamp(法穿率, 0, 100)`，与穿透率一致。
- **最小伤害**：所有伤害四舍五入后取 `≥ 1`。
- **法术暴击**：仅异人技能可触发，暴击时横幅显示 `技能名(暴)`。
- **文人抗性**（围/乱/封）：无上限，可超过 100。

## 2.8 神将技

仅头衔为"神将"的副将可选一个神将技，影响对应技能的效果。

- **配置**：副将配置页技能栏下方显示"神将技"下拉框，仅神将头衔可见；选中后对应技能名显示"(神)"后缀。
- **增幅计算**：`神将技增幅 = 增幅比例 × 副将等级`（`计算神将技增幅` 函数）。
- **伤害型技能**（乘法）：`原伤害 × (1 + 神将技增幅/100)`
  - 舍命一击、呼风唤雨、妖火燎原、五雷轰顶、巫蛊极毒、毁天灭地
- **伤害型技能**（加法）：`技能面板 + 神将技增幅`
  - 力劈华山、排山倒海
- **文人技能成功率**（加法）：`成功率 + 神将技增幅`
  - 画地为牢、趁火打劫、四面楚歌
- **固若金汤**：`抗物理 = 技能面板 + 神将技增幅`
- **凌波微步**：`速度提升 = 技能面板 + 神将技增幅`
- **金蝉脱壳特殊效果**：失败时（技能未命中或目标无文人buff），回复目标 `神将技增幅/100 × 最大气血` 点气血
- **暗渡陈仓特殊效果**：隐身成功时，回复目标 `神将技增幅/100 × 最大气血` 点气血
- **增幅比例表**：见 `common/gameCatalog.js` 中 `神将技增幅比例`
- **显示名称**：神将技对应的技能名在所有前端展示位置均带"(神)"后缀（如 `舍命一击(神)`），视为显示名称变更，底层技能不变

## 2.9 无双

副将可进入无双形态，提升属性并显示特殊前缀。

- **配置**：副将配置页无双等级右侧显示"无双几率：XX%"（`无双等级 × 0.5%`）。
- **触发条件**：
  - 第 1 回合不判断无双
  - 从第 2 回合起，每回合开始前（晚于毒buff和毁buff）根据无双几率判定
  - 无双刚结束的回合不判断（即无法每回合都无双）
- **行动顺序联动**：若回合前存在无双开启/关闭，待无双变化应用后立即重算本回合速度排名，再进入逐单位行动。
- **持续**：3 回合（如第 2 回合激活，第 5 回合出招阶段已无无双）
- **属性变化**：
  - 成长值提升（`副将无双成长增量`），气血/精力/攻击/速度同步提升
  - 当前气血/精力按比例增幅（满血无双后仍满血）
- **结束恢复**：
  - 最大气血/精力回落到原值
  - 当前气血/精力不变（可能超过最大值）
- **显示**：副将静态名称若配置 `真=true`，始终为 `(真)人物名`；无双仅战局内动态追加 `无双-` 前缀（如 `无双-(真)刘邦`）
- **动画**：`musou-activate` 步骤（单目标红框，横幅"无双"）；同回合多名副将同时触发时使用 `musou-activate-batch`（多目标同时红框，横幅"无双开启"）；`musou-end` 为静默结束

## 3. 战斗动画系统

前端根据后端返回的 `战斗过程`（步骤数组）逐步播放动画。每个步骤包含 `type`、`actorKey`、`targetKey`、`damage` 等字段。

### 3.1 动画流程（5步）

1. **高亮**：施法者亮蓝框，目标亮红框，同时横幅显示对应文本
2. **等待**：按速度档位等待（×1=2秒, ×2=1秒, ×3=0.5秒）
3. **数据变化**：前端根据步骤中的 damage/heal 推算 HP/MP 变化
4. **等待**：同上
5. **熄灭**：边框熄灭，横幅消失

### 3.2 各步骤类型与横幅

| 步骤类型 | 横幅文本 | 边框效果 | 备注 |
|---------|---------|---------|------|
| `melee` | 攻击类型名（如"暴击攻击"） | 蓝框+红框 | 5步完整流程 |
| `shock` | 反击攻击 | 蓝框+红框 | 5步完整流程 |
| `miss` | 攻击未命中 | 蓝框+红框 | 无数据变化步骤 |
| `skill-cast` + `skill-hit` | 技能名 | 蓝框+红框 | 多目标同时高亮 |
| `skill-hit`(暴击) | 技能名(暴) | 蓝框+红框 | 异人技能法术暴 |
| `skill-control` | 技能名 | 蓝框+红框 | 未命中与命中流程一致 |
| `buff-tick` | 毒发 | 红框 | 毒buff伤害 |
| `buff-detonate` + `buff-detonate-splash` | 爆炸 | 所有受影响单位红框 | 毁天灭地爆炸，合并主目标+余波 |
| `buff-block` | *(跳过动画)* | 无 | 行动失效，战况日志仍显示 |
| `item` | 使用物品名 | 蓝框+红框 | 物品使用 |
| `summon` | 招将 | 蓝框+红框 | 招将成功 |
| `summon-fail` | 招将失败 | 蓝框 | 招将失败 |
| `mount-heal` | 木牛流马 | 绿框 | 回合末回复，直接熄灭 |
| `counter` | 反震 | 红框 | 舍命一击/力劈华山/排山倒海触发反震 |
| `musou-activate` | 无双 | 红框 | 单个副将无双激活，属性提升 |
| `musou-activate-batch` | 无双开启 | 多个目标同时红框 | 同回合多副将同时进入无双 |
| `musou-end` | *(静默)* | 无 | 无双结束，属性回落 |

### 3.3 多目标技能

多目标技能（排山倒海×3、呼风唤雨×4 等）的所有目标**同时高亮**，而非逐个高亮。实现方式：
- `collectSkillBatch`：收集同一施法者、同一技能的连续 `skill-hit`/`skill-control` 步骤
- `playMultiTargetSkill`：批量播放，所有目标同时亮红框（通过 `animExtraTargetKeys`）

### 3.4 中间态推算（方案2）

前端根据初始态 + 过程步骤推算中间态，**不依赖后端返回每步快照**：
- 动画播放期间（`animating = true`），轮询 `loadBattleSnapshot` 跳过单位状态更新，避免覆盖中间态
- 动画结束后，`applyUnitStateRow` 同步最终态
- 前端动画函数中逐步推算 HP/MP 变化（`su.curHp -= dmg` 等）

## 4. 战局聊天

- **Socket 事件**：`battle-chat`（发送 + 接收）
- **限制**：单次最大 1024 字符；仅在战局中可发送
- **不持久化**：聊天记录与战局信息绑定，战局结束后永久丢失
- **前端 UI**：底部聊天框（无 tab），输入框 + 发送按钮，Enter 发送
- **消息显示**：自己名绿色，对方名蓝色

---

## 5. 服务端单位 key 约定（canonical）

为便于存储与结算，服务端 **一律** 使用：

- **`self:`** = **发起方**（挑战者）的四个单位；
- **`enemy:`** = **目标方**（被挑战者）的四个单位。

与 Mobile 界面「**当前用户 = 左侧对手为 enemy、右侧己方为 self**」可能不一致：被挑战方在界面上仍用 `self:` 表示自己队伍，故 **Socket 事件 `round-started` / `round-result` 的 payload 中带 `发起用户名`**，客户端将 canonical key **与本地 `self:`/`enemy:` 互换** 后再绑定血条与当前行动单位。

`round-started` 须向 **双方** 在线连接广播（`io.to(发起).emit` / `io.to(目标).emit`），不能只 `socket.emit` 给当前连接。

---

## 6. 回合结束与胜负展示

`checkBattleEnd` 中「我方 / 敌方」指 **canonical**：「我方」= 发起方全队倒下等。Socket `round-result` 在战局结束时额外下发 **`胜利方用户名`**（真实登录名），客户端据此显示胜利/失败，避免被挑战方把 canonical「我方」误当成自己。

## 7. 相关接口

| 通道 | 事件 / 路径 | 说明 |
|------|-------------|------|
| Socket | `battle-round-start` → `round-started` | 开始新回合；payload 含 `units`、`发起用户名`、`超时毫秒`、`服务器时间` |
| Socket | `battle-actions-submit` → `actions-submitted` / `round-result` | 提交出招；双方就绪后结算并广播 `round-result` |
| Socket | `battle-chat` → `battle-chat` | 聊天消息；双方均可发送/接收，最大 1024 字符，不持久化 |
| HTTP | `POST /api/battle/round/start` | 与 Socket 并行的回合开始（逻辑应对齐 canonical） |
| HTTP | `POST /api/battle/actions/submit` | 与 Socket 并行的提交（逻辑应对齐） |

## 8. 开战配置快照与 `日志回合键`

- **快照**：目标方在 Socket `pk-response` 同意时，服务端将 **双方** 当前配置经 `safeConfig` 规范化后写入 `battles.发起方配置快照` / `目标方配置快照`。战中 `canonicalBattleUnits`、`GET /api/battle/current` 的 `我方`/`敌方` 配置与属性 **一律优先用快照**，无列或空串的旧战局才回退读用户表。
- **`日志回合键`**：结算后会出现 `当前回合 = 刚结束回合 + 1`、而 `回合数` 仍为「刚结束回合」的一小段时间；`battle_rounds` 里 **战斗日志** 写在 **已结束回合** 那一行。`GET /api/battle/current` 用 `battleRepo.getBattleRoundRowKeyForLog` 拉取对应行，并在 `战局.日志回合键` 返回，供前端轮询与 `回合信息.回合数` 对齐，避免「有日志却合并不进来」。
- **新开回合序号**：`battle-round-start` 与提交出招时的默认回合号使用 `battleRepo.computePendingRoundNum`，**不能**简单用 `(battle.回合数 || 0) + 1`；否则在「接受 PK 后 `当前回合=1、回合数=0`、第一次开战后变为 `1/1`」时，第二次 `battle-round-start` 会把 `回合数+1` 误判成第 2 回合。
- **自动攻击**：Mobile 为开关态；开启后每回合进入出招即按「全员普攻 + 目标为对方速度排名最高存活单位」提交，并在倒计时归零时再次兜底提交（需开关仍为开）。
- **重连恢复策略**：战局页恢复以服务端 `单位状态` 为准（不再使用本地历史血蓝兜底）。若掉线后重连且战局仍在，前端直接同步最新状态，不回放历史动画步骤。

## 9. 战局数据持久化与录像回放

- **`battles` 表**：战局元数据（参与者、状态、回合进度、**双方配置快照**、时间戳）
- **`battle_rounds` 表**：每回合出招 + 战斗日志 + **战斗过程**（动画步骤数组）
  - `战斗过程` 列（V5 迁移新增）：存储 `resolveRound` 返回的 `过程` 数组，供录像回放使用
- **聊天记录不持久化**：战局结束后丢失
- **录像回放**：通过 `battles`（配置快照）+ `battle_rounds`（出招 + 过程）可完整还原战斗
