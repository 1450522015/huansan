## 10.1 健康检查

**`GET /api/health`**  

- **响应示例**：`{ "状态": "ok" }`

## 10.2 认证（无需 Bearer）

### 注册

**`POST /api/register`**

- **Body**：`{ "用户名": string, "密码": string }`
- **成功**：`{ "token": string, "用户名": string }`
- **错误**：`400` 校验失败；`409` 用户名已存在；`500` 注册失败

### 登录

**`POST /api/login`**

- **Body**：`{ "用户名": string, "密码": string }`
- **成功**：`{ "token": string, "用户名": string }`
- **错误**：`400` 校验失败；`401` 用户名或密码错误；`500` 登录失败

---

## 10.3 需登录的接口（`Authorization: Bearer <token>`）

中间件校验 JWT，失败返回 **401**。

### 读取配置

**`GET /api/config`**

- **成功**：`{ "配置": object, "配置已认证": boolean }`（空配置会补默认并规范化）
- **错误**：`404` 用户不存在；`500` 读取失败

### 保存配置

**`POST /api/config`**

- **Body**：`{ "配置": object }`
- **成功**：`{ "成功": true, "配置已认证": true }`
- **错误**：`400` 缺少配置或 `validateConfigForSave` 失败（`{ "错误": string }`）；`404` 用户不存在；`500` 保存失败

### 战斗属性

**`GET /api/attrs`**  
**`GET /api/attrs?debug=1`** 或 **`?debug=true`**

- **成功**：`{ "属性": object }`；调试时额外 `调试` 分层信息
- **错误**：`404` / `500` 同配置接口语义

### 当前战局详情

**`GET /api/battle/current`**

- **成功（无进行中战局）**：`{ "战局": null }`
- **成功（有进行中战局）**：`{ "战局": { id, 状态, 当前回合, 回合数, 日志回合键, 发起用户名, 目标用户名, 战况文本系统累计 }, "我方": { 用户名, 配置, 属性 }, "敌方": { 用户名, 配置, 属性 }, "回合信息": ..., "单位状态": [{ key, 气血, 精力, 排名, buff }] }`
  - **`回合信息`**（有已结算回合行时）：除 `回合数`、`发起方出招`、`目标方出招`、`战斗日志` 外，含 **`战况文本用户`**：`string[]`，与最近一次 `round-result.战况文本用户` 同源，供重连后战局页「系统」栏恢复本回合战况（本回合行动摘要 + `—— 下一回合前置 ——` 起首的前置摘要）。
  - **`战况文本系统累计`**：`string[]`，自开战起按回合拼接的战况文本（与 `round-result.战况文本系统` 同源）；第 1 回合出招前通常仅含 `第1回合` 与一行 `速度排名：…`。
  - **`日志回合键`**：与 `battle_rounds` 中「当前应展示的战况」行的 `回合数` 一致（结算后会出现 `当前回合 > 回合数`，此时日志仍在上一回合行）。
  - **`我方`/`敌方`.`配置`**：战中为 **开战快照**（接受 PK 时写入库），与账号当前配置可能不同。
  - **`单位状态`**：服务端 canonical 单位实时状态快照（含 hp/mp、速度排名与 buff），用于断线重连后的战局 UI 恢复。
  - 前端恢复策略：以 `单位状态` 为权威，不使用客户端历史血蓝回填。
  - **`配置已冻结`**：双方快照列均已写入时为 `true`；旧战局可能为 `false`（仍读当前用户配置）。
- **用途**：战局页恢复与渲染双方真实数据（切换底栏后返回战局不丢失）
- **错误**：`404` 用户不存在；`500` 读取战局失败

## 10.4 管理端（当前无 Bearer 要求）

### 用户管理

**`GET /api/admin/users`**

- **Query**：`page`（默认 1）、`pageSize`（默认 10，最大 100）、`keyword`（可选）、`login`（可选，`all` 等）
- **成功**：`{ "list": array, "total": number, "page": number, "pageSize": number }`

**`PATCH /api/admin/users/:id/password`**

- **Body**：`{ "新密码": string }`（校验规则同注册密码：长度与非法字符限制见 `validatePassword`）
- **成功**：`{ "成功": true }`
- **错误**：`400` 无效 id 或密码校验失败；`404` 用户不存在；`500` 修改失败

### 战局管理

**`GET /api/admin/battles`**

- **Query**：`page`（默认 1）、`pageSize`（默认 20，最大 100）、`状态`（可选，`all`/`等待中`/`战局中`/`失去连接`/`已结束`）
- **成功**：`{ "list": [{ "id": string, "发起用户名": string, "目标用户名": string, "状态": string, "当前回合": number, "发起时间": string, "结束时间": string|null }], "total": number, "page": number, "pageSize": number }`
- **错误**：`500` 查询失败

**`GET /api/admin/battles/:id/debug`**

- **用途**：管理页「复制调试」拉取 JSON；**结构对齐** mobile 战局页「复制调试信息」按钮（`BattlePage.vue` `copyDebugInfo`）。
- **成功**：`{ "生成时间": string, "说明": string, "战况文本系统": string[], "战局与回合快照": object, "最近回合结算事件": object|null }`
  - **`战况文本系统`**：与本局 `战局.战况文本系统累计` 同源（自开战起累计）。
  - **`战局与回合快照`**：与 **`GET /api/battle/current`** 有战局时的返回体**同键**（`战局`、`我方`、`敌方`、`回合信息`、`单位状态`）；后台无登录用户视角，**优先以发起方为「我方」** 构建，失败时再换目标方（与 `buildBattleCurrentSnapshot` 一致）。
  - **`最近回合结算事件`**：取 `battle_rounds` 中 **`battle_id` 下最大 `回合数`** 的一行展开（与客户端最近一次 `round-result` / `lastRoundResult` 对齐；当前回合尚未结算时不会误用「进行中的回合键」）；并覆写内层 **`战况文本系统`** 为上述**累计**数组。`说明` 字段与手游复制包**同文**。

## 10.5 大厅（需 Bearer）

### 在线用户列表

**`GET /api/hall/users`**

- **Query**：`page`（默认 1）、`pageSize`（默认 20，最大 50）、`keyword`（可选，用户名模糊搜索）
- **说明**：只返回当前在线用户；列表项包含 `职业串`（如"男文 - 男文 - 男文 - 男武"，无配置时显示"————"）与 `配置已认证`（布尔值）
- **前端显示规则**：
  - 自己不显示 PK 按钮（`用户名 === 当前用户名`）
  - 对方 `配置已认证 === false` → 显示"准备中"
  - 对方 `配置已认证 === true` 且自己 `配置已认证 === true` → 显示"PK"（可点击）
  - 自己未认证时，即使对方已认证，PK 按钮也置灰不可点击
- **成功**：`{ "list": [{ "id": string, "用户名": string, "转数": number, "等级": number, "职业串": string, "配置已认证": boolean, "在线": true }], "total": number, "page": number, "pageSize": number }`
- **错误**：`500` 查询失败

## 10.6 Socket.IO 事件

连接需在 `handshake.auth.token` 传入 JWT，验证失败连接被拒。
连接状态：`offline`（手动离线，不自动重连）| `connecting`（重试中）| `online`（已连接）。

### 服务端 → 客户端

| 事件 | 数据 | 说明 |
:|------|------|------|
| `欢迎` | `{ 消息: string }` | 连接成功欢迎 |
| `online-change` | `{ 在线列表: [{ id, 用户名 }] }` | 在线列表变化时广播 |
| `pk-sent` | `{ 目标用户名, 目标转数, 目标等级, 目标职业串, 发起转数, 发起等级, 发起职业串 }` | 发起方确认挑战已发出，附带双方信息 |
| `pk-request` | `{ 发起用户名, 发起转数, 发起等级, 发起职业串 }` | 被挑战方收到 PK 请求（上线时补推未处理的邀请） |
| `pk-cancel` | `{ 发起用户名, 目标用户名 }` | 对方取消了 PK 挑战 |
| `pk-result` | `{ 目标用户名?, 同意: boolean, 原因: string }` | 发起方收到 PK 结果 |

### 客户端 → 服务端

| 事件 | 数据 | 说明 |
:|------|------|------|
| `pk-challenge` | `{ 目标用户名: string }` | 发起 PK 挑战（双方必须已认证，否则返回错误原因） |
| `pk-cancel` | `{ 目标用户名: string }` | 发起方主动取消 PK |
| `pk-response` | `{ 发起用户名: string, 同意: boolean }` | 被挑战方回复 |
