# 04 · 配置数据模型（中文 JSON）

[← 返回索引](./README.md)

---

## 4.1 总结构

用户保存在 SQLite 表 `users` 字段 **`配置`**（JSON 文本）中的对象，根级键（均为中文）：

| 键 | 含义 |
|----|------|
| `主将` | 玩家主角色 + 装备 + 坐骑 |
| `副将列表` | **长度 10** 的数组；每项为一条副将数据，并含 `已配置`、`状态`（`战`/`休`，界面展示为 **已战** / **已休**）。旧存档若仍含 `副将1`～`副将3`，读入时由 `normalizeConfigDeep` 自动迁移到前三槽并标记为「战、已配置」。 |
| `副将上阵顺序` | **最多 3 个** 槽位下标（0-based），表示当前「已战」的**先后次序**；与 `副将列表[n].状态 === '战'` 一致。第 4 个槽设为已战时，会将**原排行第 3** 的槽改回休并由 `gameCatalog` 中的 `副将槽设为已战` 维护。 |

另有字段 **`配置已认证`**（库内 0/1）：仅当 **POST `/api/config` 校验通过并成功保存** 后为 `true`；本地改动未再次通过保存校验则客户端显示「未认证」（与是否改回内容无关，见当前任务说明）。

**主将名称** 不要求写入配置：产品约定 **主将显示名 = 登录用户名**（由客户端展示）。

## 4.2 主将（`主将`）字段说明

| 字段 | 类型/结构 | 说明 |
|------|-----------|------|
| `角色分类` | 字符串 | `男武` / `男文` / `男异` / `女武` / `女文` / `女异`，**同时表达性别+职业**，不再单独存 `性别`、`职业` |
| `等级` | 数字 | 1–160 |
| `转数` | 数字 | 0–3；当前 UI 仅开放 **3 转** |
| `属性分配` | 对象 | `{ 体质, 智力, 力量, 敏捷 }`，规则见 [07-属性点与风格.md](./07-属性点与风格.md) |
| `装备` | 对象 | 六个部位，顺序见 [05](./05-装备坐骑宝石与技能表.md) |
| `坐骑` | 对象 | `{ 种类, 转数, 等级 }` |
| `帮派` | 对象 | `{ 主抗性, 副抗性 }`，见 [主将.md](./主将.md)；可空、只主、只副或双选（双选不可同项）；主 +20、副 +10 |
| `天赋` | 数组（长度 4） | 每项 `{ 名称, 等级 }`，`名称` 可为 `null` |
| `技能` | 数组（长度 4） | 每项 `{ 名称, 等级, 熟练度 }`，名称由 `角色分类` **固定**，不可改槽位技能名 |

## 4.3 副将（`副将列表` 每一项）字段说明

与主将相比：

- **无** `装备`、`坐骑`。  
- **有** `宝石`：数组，**最多 9 条**，每条 `{ 属性, 数值 }`，属性仅限九类抗性（见 [05](./05-装备坐骑宝石与技能表.md)）。  
- **槽位元数据**：  
  - `已配置`：布尔；`false` 时在主页显示 **「无」**，人物应为空；选择具体 `人物` 后为 `true`。  
  - `状态`：`战`（上阵）或 `休`（休息）；**最多 3 个槽** 可为 `战`，超出时规范化会改为 `休`。  
- **身份与无双**（见 [副将.md](./副将.md)）：  
  - `头衔`：字符串，当前实现仅 **`神将`**（可扩展国士等）。  
  - `人物`：字符串；已配置时须为当前头衔下可选副将名（神将表见 `gameCatalog` 中 `副将神将名称列表`）。  
  - `星级`：整数；神将为 **4–6**，默认 **6（满星）**。  
  - `真`：布尔，默认 **`true`（是）**。  
  - `无双等级`：整数 **0–160**，默认 **160**。  
  - `默契度`：整数 **0–500000**，默认 **0**；按与满值的比例折算命中率、暴击率、反击率、致命率、躲避率、反震率（满值加成见 `gameCatalog` 中 `副将默契战斗加成`），并计入该副将战斗属性汇总。  
- 其余：`职业经历`（四世，与主将同结构；**四世前缀性别以副将表为准**，与主将性别无关）、`等级`、`转数`、`属性分配`、`天赋`、`技能` 含义同主将；旧数据仅有 `角色分类` 时仍由 `migrate职业经历` 兼容。

**战斗属性**：`GET /api/attrs` 仍返回 `副将1`～`副将3` 三个键，由服务端按 **槽位顺序取前三个「战」且已配置** 的项展开（不足则用默认副将体补位），见 `展开战斗用副将占位`。

## 4.4 装备槽位（主将 `装备`）

每个部位一个对象：

```json
{
  "名称": "字符串",
  "词条": "部分部位需要，见装备表",
  "宝石": [ { "属性": "…", "数值": 15 }, null, null ]
}
```

- **`宝石`**：固定 **3 个槽位**，未镶嵌用 `null`。  
- **`数值`**：1–15（当前产品默认上限 15）。

## 4.5 规范化 `normalizeConfigDeep`

从数据库读出或客户端提交的配置，都会经 **`normalizeConfigDeep`**（定义在 [`common/gameCatalog.js`](../../common/gameCatalog.js)）处理后再保存或参与计算。主要行为：

1. **补全缺省**：与 `getDefaultConfig()` 合并，避免缺字段。  
2. **角色迁移**：若旧数据只有 `职业`+`性别`，会转换为 `角色分类`。  
3. **属性点修正**：`修正属性分配(等级, …)`，防止超过 `等级×8` 或低于每维 `等级`。  
4. **装备槽**：每部位走 `normalize装备槽`；旧键 **`项链`** 会迁移到 **`项饰`**。  
5. **天赋/技能**：补齐 4 槽；技能名与当前世的 `职业经历` / `角色分类` 固定表对齐。  
6. **副将列表**：长度压到 **10**；`已配置` 为假时强制 `人物` 空、`状态` 为 `休`；`战` 超过 3 时按槽位下标保留前三个。  
7. **副将身份**：`头衔`、`人物`、`星级`、`真`、`无双等级` 经 `normalize副将*` / `normalize无双等级` 修正（与 [副将.md](./副将.md) 一致）。
